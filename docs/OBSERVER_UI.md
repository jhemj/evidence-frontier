# 읽기 전용 조사 화면 계약

`ui/observer/`는 조사 원장을 별도 스냅샷으로 읽는 관찰 화면이다. 기본 화면은 중앙 정적 안내자와 가설·이유·단서·검사 설명 말풍선, 핵심 사건 시간축, 보고서로 구성된다. 질문·주장·검사·원문 상세와 작업 이력은 선택할 때 대화상자로 열린다. 화면 열기·선택·필터·재접속은 새 모델 호출이나 조사 명령을 만들지 않는다. UI가 조사 엔진의 의미 정확도나 효율을 개선했다는 뜻은 아니다.

## 공통 스냅샷

`scripts/observer_snapshot.py`는 SQLite를 읽기 전용 트랜잭션으로 읽는다. `workbench/observer_view.py`는 새로운 판단 없이 표시 계약을 조립한다. 사건·차수·모드·원장 위치와 객체별 버전 참조를 검증하며, 정정·누락·역순 수신 시 낡은 판단을 최신으로 표시하지 않는다. 원문·파일명·모델 출력은 비신뢰 표시 데이터다.

작업 상태의 확인 시점과 판단 기준 시점은 다르다. 실제 작업 참조가 없으면 실행 중이라고 만들지 않는다. 다음 검사는 후보·예정·실행·자료 필요를 구별하며, 검사 성공을 가설 입증으로 승격하지 않는다. UI에는 검사 목적과 근거에 기반한 조사 설명을 제공하고 모델 내부 사고 전문을 전달하지 않는다.

AI 검토 대상은 해당 요청에 저장된 `required_dossiers`와 실제 제시 기록에서 읽는다. 현재 단서의 바뀐 제목을 과거 입력에 소급 적용하지 않는다. 명령 문자열·출처와 생략한 입력 기록 수를 예시로 표시하며, 아직 검토 중인 기록을 채택된 사실로 승격하지 않는다. 입력 등록만 있으면 검토 입력 준비로, 명시적인 요청 시작 기록이 있으면 검토 중으로 표시한다. 입력 시각은 AI 실행 시작 시각이 아니다.

실패 설명은 영향을 받은 검토 대상, 도구 확인·입력 준비·답변 검증·요청 실패의 구분과 남은 공백을 보여준다. 인용 검증 거부를 전송 실패로 쓰지 않으며, 독립 부분 채택을 지원하므로 일부 답변 거부를 전체 묶음의 폐기로 단정하지 않는다. 세부 오류와 요청 참조는 작업 상세에서 확인한다. 표시 설명을 위해 추가 모델 요청이나 조사 계획을 만들지 않는다.

검사 평가는 원장의 `latest_assessment`와 `assessment_status`를 함께 읽는다. 물리 결과가 변경되어 미평가로 돌아간 검사는 이전 평가 이력을 현재 결과로 표시하지 않는다. 도구의 결과 범위는 `test_intent.result_scope.scope`에서 읽으며, 부분 결과·잘림은 논리 판별과 별도다.

## 포식이의 설명

기본 읽기 순서는 “어떤 가설인가 → 왜 그렇게 보는가 → 무엇을 확인하는가 → 어떤 결과가 판단을 바꿀 수 있는가”다. 표시 문구는 원장에 이미 있는 가설·해석·정확히 결속된 사실·검사 목적과 조건을 재사용한다. `briefing.js`는 읽기 전용 표시 조립기이며 새 계획이나 판단을 생성하지 않는다. 결과 기준이 없으면 없다고 표시한다. 검사 성공 조건을 의심 가설의 입증으로 번역하지 않는다. 승인된 운영 설명을 지지하는 결과도 불확실성 해소가 될 수 있다.

실제 작업의 강조는 현재 job과 검사, 질문, 가설 및 입력 근거의 명시적인 연결을 요구한다. 질문 ID가 같더라도 서로 다른 파일을 검사할 수 있으므로 가설의 근거와 `TestDesign`의 필수·기준 관측 참조가 겹치지 않으면 그 가설의 검사로 표시하지 않는다. 이 교집합은 출처 연결일 뿐 의미 정확도나 인과관계 검증은 아니다. 사용자가 다른 가설을 선택하는 동작은 열람이며 실행·우선순위를 바꾸지 않는다.

가설의 현재 지지 판단은 엔진에 보존된 근거 digest, 검토 revision 및 현재 작업·증거·세대가 일치할 때만 표시한다. 최소 관측 목록만으로 전체 의존성이 최신이라고 판단하지 않는다. 같은 읽기 트랜잭션에서 미인용 동일 객체 근거도 대조하며, 검증 한도(5,000개 행 또는 직렬화8MB)를 넘으면 최신성 미확인으로 남긴다. 지난 가설과 선택한 과거 버전은 현재 실행·유력 판단으로 강조하지 않는다. 비활성 말풍선은 덜 진한 배경과 글자색으로 구별하되, 실패·정정 경고를 흐리게 만들지 않는다.

기본 화면에는 현재 설명 한 묶음만 표시한다. 이전·다음 버튼은 실제 보존된 가설 설명과 개정 이력을 하나씩 넘기며, 현재 설명으로 즉시 돌아갈 수 있다. 설명 시각은 해당 원장 개정 시각을 사용한다. 열람 중 새 판단이 도착해도 읽던 설명·포커스를 강제로 옮기지 않는다. 중요한 정정과 실제 작업 상태는 별도로 유지한다. 표시 순서는 열람 순서이지 가설의 확률·증거 지지 순위가 아니다.

공통 스냅샷에는 설명 이력의 버전·개정 번호·시각만 포함한다. 과거 설명 본문은 사용자가 넘길 때 고정 GET 경로로 읽으며 사건·차수·소유 가설·원장 이력 버전을 대조한다. 다른 버전이면 대체하지 않고 재동기화를 요구한다. 같은 가설을 다른 작업에서 재검토한 과거 문맥은 당시 작업·세대 참조로 보존하며 현재 작업에 소급 연결하지 않는다. 사건·증거 소유권이 다른 개정은 차단한다. 과거 설명은 당시 채택된 공개 설명이며 현재 사실 판정이나 모델 내부 사고가 아니다. 현재 검사를 과거 계획으로 소급 연결하지 않는다. 과거 설명에서 원문을 열 때는 현재 스냅샷의 보존 버전임을 명시하며, 당시 원문 버전·최신성을 증명한다고 표시하지 않는다. 보존되지 않은 설명은 생성하지 않는다.

## 시간과 보고서

행위 시각, 기록 시각, 파일 시각 및 추정 근거를 구별한다. 절대 시각으로 비교할 근거가 없는 항목은 별도 영역에 보존한다. 시간순 배치는 인과관계를 뜻하지 않는다. 같은 원본·같은 행위·같은 물리 결과 재사용은 서로 다른 관계다.

보고서가 없으면 미생성으로 표시한다. 기존 보고서는 사용한 역사적 판단 묶음을 유지하고 정정 영향은 별도 표시한다. 모델에 제시되지 않은 범위와 불확실성을 숨기지 않는다.

기본 시간축은 선택한 질문만이 아니라 사건 전체의 채택된 핵심 단서를 시간순으로 보여준다. 제목은 결속된 원문 필드의 의미만 일상 문장으로 표현하고, 살펴보는 이유는 기존 AI 해석으로 구별한다. 파일 시간은 행동 시간으로 바꾸지 않는다. 처음12개 및 더보기는 표시량 제한이며 가설·원문 수 제한이 아니다. 전체 연결 자료와 시각 미상·비교 불가 자료는 별도로 열 수 있다.

HTML/Word 및 임원용/분석가용은 같은 canonical 주장 버전을 참조한다. 버전이 바뀌면 기존 보고서의 정정 영향을 표시하며 파일 내용을 조용히 교체하지 않는다. 보존 원문의 추가 읽기는 선택한 관측·정확한 버전·문자 범위만 허용하고 임의 파일 경로나 증거 URL을 열지 않는다.

`complete`, `quiescent`, `resource_limit`는 실행 상태이며 질문 규명 완료가 아니다. 종료 시각은 해당 사건이 참조한 epoch에서 읽고, 기록되지 않은 세부 종료 이유는 만들어 넣지 않는다. 새 실행은 종료·예산 상한·일시정지 뒤 모델 호출 없이 부분 보고서 마감을 요청할 수 있다. 마감 요청/생성 실패/마감 이후 범위 변경은 별도 상태로 보존한다. 과거 종료 사건에 요청을 소급 생성하거나 보고서 생성으로 미완료 작업을 성공 처리하지 않는다.

## 배포와 표시 안전

`scripts/serve_observer.py`는 loopback에 바인딩하고 고정 GET/HEAD 경로만 제공한다. 원장, 동결 조사 코드, 스케줄러를 변경하지 않는다. 표시에는 안전한 DOM 삽입, CSP 및 외부 자원 차단을 사용하며 증거 URL 미리보기나 명령 실행 링크를 만들지 않는다.

Live2D SDK나 모델은 포함하지 않는다. 향후 승인된 렌더러는 표시 상태만 받고 실패 시 정적 안내자로 전환한다. 효과가 비활성화돼도 현재 작업·실패·정정·원문·보고서에 접근할 수 있어야 한다. 모션 감소와 숨김 탭 정지를 지원한다.

## 남은 실증

계약 회귀와 보존 데이터 관찰은 실제 사건 분석 완료, 분석가의 이해 정확도 또는 운영 로컬 모델의 효율 검증이 아니다. 사용자 이해도 시험, 로컬 단일 모델 환경의 메모리·투영 지연·모델/도구 지연 비교, 실제 Windows 운영 및 선택적 Live2D 비용 측정은 별도다. UI를 이유로 조사 실행이나 모델 역할·스케줄을 바꾸지 않는다.
