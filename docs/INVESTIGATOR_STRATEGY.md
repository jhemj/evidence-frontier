# 질문과 가설 중심 조사 구조

Frontier는 로컬 또는 신뢰된 사설 모델의 조사 제안과, 하네스의 실제 실행·근거 채택을 분리한다. 이 문서는 공개 코드의 구조를 설명하며 실제 사건 결과나 운영 환경의 주소를 포함하지 않는다. 모델 의미 정확도나 전체 사건 조사 완료를 보장하는 문서는 아니다.

## 실행과 근거의 책임

Controller와 Worker가 읽기 전용 도구 실행, 범위 검증, 예산 예약, 원문 보존을 담당한다. Native 조사자에는 직렬화한 입력만 전달하며 Controller·Store 객체나 임의 셸 실행권을 제공하지 않는다. 모델은 질문, 경쟁 설명, 검사 및 결과 해석을 제안한다. 채택은 출처·범위·리터럴·작업 버전 검증을 거친다.

관측, 좁은 사실 주장, 해석, 가설, 질문, 논리 검사와 물리 실행은 별도 참조를 가진다. 설정·명령 기록은 실행 성공이나 목적을 자동으로 입증하지 않는다. 서로 다른 파일, 반복 발췌 또는 동일 결과 재사용을 독립 근거로 합산하지 않는다.

## 질문과 후속 검사

`case_memory.py`와 `question_engine.py`는 질문 및 검사 원장을 유지한다. 검사는 실제 도구의 능력과 입력 조건을 통과해야 실행되며, 지지·반박·판별 불가 조건과 결과 범위를 보존한다. 같은 유효 요청의 결과는 재사용할 수 있지만 다른 객체·파티션·범위는 구별한다.

원문 페이지, 근거 선택, 비교 및 종합은 `review_stream.py`와 관련 모듈에서 처리한다. 중간 페이지 노트는 최종 판단이나 원문을 대신하지 않는다. 미제시·미검토·검색 범위 밖은 부재나 반증으로 바뀌지 않는다. 변경된 관련 근거는 기존 판단과 종합의 최신성을 제한한다.

## 재사용 가능한 조사 절차

`workbench/procedures/`는 플랫폼별 탐색, 근거 선택, 시간 해석, 경쟁 설명 및 보고 원칙을 제공한다. 문서의 버전과 해시는 실행 설정에 결속된다. 절차는 조사 방법을 안내할 뿐 사건별 정답이나 특정 이름의 정상성 목록을 제공하지 않는다.

제품은 최대 두 개의 local 또는 trusted-private 모델 연결과 역할 배정을 지원한다. 기본 `review_concurrency=1`이며, 더 큰 값은 허용된 독립 검토 묶음의 동시 실행 범위다. 단일 조사 그래프 전체 병렬화나 실제 처리 속도 보장은 아니다.

## 평가와 현재 한계

구조 회귀, 합성 의미 평가, 실제 모델 계약 검사 및 실제 증거 E2E는 다른 검증이다. `scripts/audit_question_progress.py`는 질문·검사 상태, 물리 결과 재사용, 실패를 포함한 사용량을 측정한다. 정확도와 중요 단서 누락률은 전문가 정답 집합 없이 만들어내지 않는다.

코드가 질문 중심 구조를 제공한다는 사실만으로 효율적인 검사 선택·가설 발전·종결이 입증되지는 않는다. 모델 계약 복잡성, 입력 재전송, 비판별 검사 및 재검토 비용은 별도 측정과 개선이 필요하다. 테스트 전용 외부 모델 어댑터의 결과를 운영 로컬 모델 품질이나 성능으로 일반화하지 않는다.
