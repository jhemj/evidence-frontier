# 자동 침해조사 구현 계획

목표: 사용자는 증거를 연결하고 한 번 조사 시작을 누른다. 로컬 AI와 실제 포렌식 도구가 내용 조사, 추가 조사, 경쟁 설명 검증, 결과 패키지 생성을 수행한다. 사용자가 매번 도구를 선택하거나 질문해야 하는 흐름을 없앤다.

## 기준 변경

파일 개수와 파일시각 수집은 준비 작업이다. 조사 기능의 합격 기준은 관측 원문 → 실제 검사 → 가설 갱신 → 반대가설 검사 → 근거가 연결된 결과다. 사용자 제공 휴대형 침해조사 패키지의 분석 깊이를 기준으로 삼되, 사건 자료·예시 보고서 원문은 배포 소스에 포함하지 않는다. 문서 양식은 추후 사용자 템플릿으로 교체한다.

## 단계

1. 기존 무결성·파티션 검증 기록을 보존하고 원본 구성이 같은지 확인한다. 재분석을 위해 불필요하게 E01 전체 해시를 반복하지 않는다.
2. 상세 내용 검색 전에 10개 필수 조사 영역을 영속 저장한다.
3. Linux 루트의 계정·인증·셸 명령·cron·서비스·설정·점검 기록·ELF·로그 보존 범위를 읽는다. XFS와 ext 의존성을 이미지에 포함한다. 원문 파일과 locator·SHA-256을 별도 파생 증거 볼륨에 보존한다.
4. 로컬 모델은 허용된 도구를 구조화된 요청으로 호출한다. 검색 결과 → 원문 재확인 → 정적 검사/백업 목록 등 서로 다른 검사를 이어간다. 실제 작업 영수증과 새 관측만 판단 입력으로 사용한다.
5. 의심 행위와 정상 관리·점검 가능성을 비교한다. 설정, 호출, 실행, 통신, 목적 달성을 구분한다. 가설별 지지·반증·자료 공백과 판정 이력을 보존한다.
6. 그래프의 실행 상태와 실제 worker 작업 원장을 분리한다. 중단/재시작 시 이미 발행된 도구 결과를 다시 사용한다. LangGraph + SQLite checkpointer를 채택했다. ChatGPT Pro와 이견 없이 합의한 계약은 [도입 결정](LANGGRAPH_DECISION.md)에 기록했다.
7. 조사 종료 사유·미확인 범위·AI 검토 후보를 포함한 결과와 원문 패키지를 자동 생성한다. 타임라인·지표 후보·가설·분석 장부·증거 매핑과 SHA-256을 함께 제공한다.
8. 실제 Docker 서비스와 로컬 모델, 실제 E01에서 버튼 시작부터 추가 도구 실행·패키지 내려받기까지 검증한다. parser 정확성 및 중단/재시작은 별도 재현 가능한 테스트로 확인한다.

## 핵심 검증

- 10개 조사 영역이 상세 수집보다 먼저 등록되는가.
- AI가 요청한 도구가 실제 실행되고 그 결과가 다음 판단에 반영되는가.
- 점검 스크립트의 악성코드 문자열을 감염 근거로 오인하지 않는가.
- cron 호출을 실행·통신 성공으로, 부분 수집을 전체 부재로 바꾸지 않는가.
- 수집되지 않은 영역과 전용 파서가 없는 자료를 구분하는가.
- 보고서 관측 ID → 원문 증거 ID → 상대경로·locator·실제 SHA-256이 일치하는가.
- 연결 해제한 증거가 새 분석·보고서·원문 다운로드에서 제외되는가.
- 원본은 읽기 전용이며 Windows/Ubuntu에서 동일 컨테이너 계약을 사용하는가.
