# 침해 탐지 개선과 증거 타임라인

## 구현 계약

사건 고유 키워드나 정답 파일명을 제공받지 않는 조사도 지원한다. 기본 탐지는 원문 스트림에서 수행하고, AI에 전달하는 간소화된 자료와 분리한다. 단서 없는 기본 영역도 검토하며, 같은 원문을 재검색한 결과를 독립 발생원으로 취급하지 않는다.

1. 지원 파일시스템의 할당 경로를 열거하고 파일·자료군별 처리 범위를 기록한다.
2. 로그·설정의 스트리밍 파싱, 일반 행위 패턴, 전체 파일 의미를 지킨 YARA/ELF 검사, 이미지 내부 패키지 메타데이터 대조로 단서를 만든다.
3. 기본 영역 및 단서마다 원문 참조를 연결해 AI가 정황과 정상 관리 등의 경쟁 설명을 검토한다.
   고정 규칙에 걸리지 않은 AI의 도구 기반 가설도 별도 검토 대상으로 연결한다. 이전 AI 문장은 가설이며 원문 증거로 계산하지 않는다.
4. 구체적인 추가 검사는 가설·도구·경로/검색어·입력 지문·성공 조건과 함께 영속 작업 원장에 등록한다. 실제 실행 결과를 받은 다음 다시 판단한다.
5. 각 판단과 검토 실패·연기 상태를 보존한다. 최종 요약이 원장에 있는 단서를 삭제하지 못한다.

**확인 / 유력 / 미확인**은 주장 범위의 신뢰도다. 문자열·코드·등록 설정·호출·실행·목적 달성은 서로 다른 주장이다. YARA 일치나 패키지 DB 불일치만으로 실제 침해를 확인하지 않는다. 이미지 내부 패키지 DB는 신뢰된 외부 원본이 아니다. 자료 부재·파서 실패·미검사는 반증이나 정상의 증거가 아니다.

## 화면

조사 화면 첫 영역은 전체 폭의 타임라인이다. 기록 분포와 세 판단 단계의 점을 보며 구간을 선택하고, 핵심 카드에서 원문 근거를 열 수 있다. 시간은 KST로 표시하고 원문의 시간 추정 근거를 상세 화면에 보존한다. 파일 수정 시각을 행위 시각으로 바꿔 표시하지 않는다. 날짜 없는 자료에는 임의 날짜를 부여하지 않는다.

AI는 핵심·참고·반증됨 역할을 판단한다. 반증으로 철회된 해석은 기본 핵심 목록에서 빠지지만 원문은 유지되며, 이전/새 판단·변경 이유·**판단 갱신 시각**이 이력에 남는다. 이 시간은 **사건 발생 시각**과 구분한다. 선과 시간상 인접성은 인과관계나 행위 지속 시간을 뜻하지 않는다.

실제 worker 결과가 채택되면 카드가 추가되고, AI 검토가 저장될 때 상태가 갱신된다. 장시간 파일 검사 중에는 진행 수치를 표시한다. 아직 완료되지 않은 개별 파일 내용을 실시간 결과처럼 만들어 표시하지 않는다. 카드 목록은 12개씩 더 볼 수 있고 전체 원문 이벤트는 보고서의 TIMELINE.csv에 보존한다. 화면 분포는 색인 관측 묶음 기준이며 전체 원문 이벤트 개수와 구분한다.

## 범위와 자원

- 기존 기본 원문 보존: 파일 16 MiB, 합계 512 MiB. 이 한도와 별도로 스트리밍 파싱·헌팅을 수행한다.
- 스트리밍 읽기 기본 8 GiB: 설정 1 GiB, 로그 3 GiB, 바이너리 3 GiB, 기타 1 GiB. 파일 256 MiB, 전체 ELF 검사 32 MiB. 초과는 partial/deferred이며 음성 판정이 아니다.
- 선택 경로 및 파일 형식만 검사한다. journal/sar/패킷, 압축 내부 바이너리·아카이브의 내용 파싱, 삭제·미할당·swap·별도 마운트 볼륨 연결은 미지원으로 남는다. 압축 텍스트 로그와 압축 설치 묶음을 구별한다.
- 파일별 `hunt_files.ndjson`, `manifest.json`의 `hunt_coverage`, 패키지 대조 영수증을 결과에 포함한다. 원문 바이트·압축 해제 바이트·파생 비교 JSON은 위치 기준이 다르다.
- 기본 영역 3개와 단서별 검토를 분할한다. 한 실행에서 최대 96개 dossier, 배치당 3개, 최대 3회 판단, 추가 도구 작업 최대 24개다. 각 모델 요청은 최대 2회 시도하고 실패 상태를 보존한다. 한도 중단은 조사 완료와 구분한다.
- 검토 예산은 권한·지속성·실행·미분류·일반 설정 변경 자료군에 먼저 각 12개까지 배정한 뒤 순환 배분한다. 일반 설정 변경은 최대 24개로 제한한다. 재시도 시 이전에 연기된 같은 단서는 자료군 내에서 먼저 처리하고, 중요 자료군의 미검토 개수를 별도 보고한다. 이 분류는 검토 순서이며 침해 판정이 아니다.
- 동일 내용의 바이너리도 경로별 판단을 유지한다. 해시가 같은 원문 저장 객체만 재사용하며 대표 파일의 정상 해석을 복사본에 전파하지 않는다. 파일 인벤토리는 경로별 UID/GID/mode/시각을 보존하고 직접 다시 읽는 도구는 해당 메타데이터도 반환한다. capability와 패키지 소유자·권한 기준 비교는 아직 수행하지 않는다.
- Windows/Ubuntu 모두 Linux Docker worker를 사용한다. 대용량 파일시스템에서는 `.env`의 `WORKER_MEMORY=12g` 등 추가 메모리가 필요할 수 있다. 실제 대형 XFS 검사에서 약 9.3 GiB의 프로세스 메모리를 관측했으며, 12 GiB 한도에서 원문 검사를 완료했다. 호스트와 Docker VM의 가용 메모리를 고려해야 한다.

분석 버전 변경 시 기존 결과와 무결성 영수증을 보존하고 새 작업을 생성한다. 현재 원문 조사 실패를 이전 버전 결과로 대신하지 않는다. 원문 조사 재시도는 그 결과에 의존하는 AI·보고서 작업을 새로 생성한다.

## 검증

새 규칙의 변형 및 정상 점검 명령, 압축 로그, 청크 경계와 마지막 행, 전체 ELF 검사 제한, 압축 바이너리의 텍스트 파싱 방지, AI 오류, 추가 도구 실행 후 재판단, 재시도 중복 방지, 반증 이력·미확인 시각, 연결 해제 시 원문 보존을 테스트한다.

`scripts/make_hunt_fixture.py`는 무해한 내용을 가진 E01을 만든다. 576 MiB의 선행 자료 뒤의 로그·코드와 실제 ELF 구조, 압축 인증 로그를 포함한다. 이 파일의 코드는 실행하지 않는다. `hunt-truth.json`에 저장된 필수 단서 5종과 정상 대조 경로를 도구 결과·보고서에서 대조한다. 작은 합성 자료의 통과를 실제 사건의 탐지율로 일반화하지 않는다.

설치된 모델을 지정해 `python scripts/run_investigation_e2e.py --fixture hunt --model 모델이름`으로 Docker 서비스의 생성·연결·실제 모델·보고서 검증을 재현한다. 첫 fixture 생성에는 임시 디스크 공간 약 2 GiB가 필요하다. 규칙 단위 검사를 네이티브에서 모두 실행하려면 `uv sync --frozen --group worker` 후 `uv run pytest`를 사용한다. Docker의 `test` target은 실제 worker 의존성도 포함한다.

2026-09-14 GPT Pro와 프로젝트 내 새 채팅에서 5차 협의 후 위 계약과 타임라인 설계에 추가 이견 없이 합의했다. 실제 증거 내용은 협의 채팅에 전송하지 않았다. 실제 Windows Docker Desktop 검증과 Ubuntu 호스트에서의 검증 여부는 구분해서 기록한다.
