# Linux와 Windows 증거 지원 범위

새 사건에서 선택하는 OS는 호스트 PC가 아니라 조사 대상 증거의 운영체제다. 잘못 선택하면 새 사건을 만들며 기존 사건의 실행 바인딩을 바꿔 재해석하지 않는다. 플랫폼별 수집과 도구 허용 범위를 분리하고, 근거 검증·반론·보고서 계약은 공유한다.

## Windows 수집

지원 입력은 이미지, 단일 EVTX, 정규화 NDJSON 또는 검증된 안전 ZIP이다. 확장자만으로 파싱 성공을 보장하지 않는다. Windows 수집기는 지정된 이벤트 로그 채널, 예약 작업 XML, 현재 Defender 예외와 SRUM 자료를 제한된 범위에서 읽는다. 후속 도구는 보존 자료의 `search`, `read_source`, `correlate`로 제한한다.

관측에는 원시 필드·소스·해시·위치·파싱 범위와 실패를 남긴다. Task 설정은 실행 인스턴스가 아니며, 기록된 경로와 실제 해결된 경로는 구별한다. 정규화 산출물 검증은 원본 디스크나 원본 EVTX 검증과 다르다. 안전 ZIP의 형식·멤버·해시·크기·경로를 검증하고 실행 페이로드를 복원하거나 실행하지 않는다.

## 지원하지 않는 범위

Windows 전체 호스트 조사 완료를 주장하지 않는다. 메모리·패킷, 삭제/미할당 복구, BitLocker 키 입력, VSS·Windows.old 재구성, USN 복원, 백신 페이로드 해독 및 native Prefetch·Amcache·Shimcache·브라우저 파서는 현재 지원 범위가 아니다. 파싱 부분 성공과 공급자별 의미 해석의 완전성은 다르며 미지원 범위는 보고서에 남긴다.

## 공통 보고와 검증

임원용 요약과 분석가용 상세 HTML·Word는 같은 불변 판단 묶음을 사용한다. 파일 시각·설정·호출·실행·통신·목적을 구별하고 미확인 범위와 반대 설명을 보존한다. 합성 회귀가 실제 Windows 골든 이미지나 Windows 호스트 설치 시험을 대신하지 않는다. 공개 저장소에는 코드와 합성 fixture만 포함하고 실제 사건 산출물은 포함하지 않는다.
